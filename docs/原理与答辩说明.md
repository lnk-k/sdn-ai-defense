# 从链路层理解这个课设

## 1. 先看普通通信

h1 想访问 server，数据先经过 s1，再经过 s2。数据链路层把网络层交下来的内容封装成以太网帧，交换机读取 MAC 地址决定从哪个端口转发。

在这个项目中，交换机由 Open vSwitch 软件实现；虚拟主机由 Mininet 创建。虽然都运行在一台机器上，它们使用 Linux 网络协议栈、虚拟网卡和真实进程通信，产生的包数和吞吐量是实际测量值。

## 2. 为什么会出现异常影响

s1 到 s2 的链路限制为 10 Mbit/s。h1 的正常业务与 h3 的场景流量共享这段链路。h3 发送大量包时，队列和带宽会被占用，h1 可能出现吞吐量下降。

流量大本身不证明恶意。项目也安排了正常 UDP 负载场景，并统计误封，检验系统是否把正常通信误判。

## 3. SDN 让程序能修改交换机规则

OS-Ken 是编写控制器的框架；OpenFlow 是控制器与交换机之间的协议。交换机转发数据，控制器获取状态、下发规则。控制器不需要接收每一个数据包，也不负责给每个包运行一次 AI。

本项目使用两张表：

```text
一个帧进入 s1
      ↓
table 0：是否匹配临时封禁规则？
      ├─ 是：丢弃，计入丢弃规则的计数器
      └─ 否：匹配入口统计规则，累计包数/字节数，进入 table 1
                                                   ↓
                              根据目的 MAC 转发；必要时询问控制器
```

table 0 中，封禁规则优先级为 400，统计规则为 100。OpenFlow 数字越大，匹配优先级越高。丢弃规则的指令列表为空，数据包不会继续进入转发表。

## 4. 交换机统计怎样变成特征

交换机返回累计计数。例如前一次是 1,000 包，1 秒后是 1,400 包，那么最近一秒为 400 包/秒。代码使用实际时间差，不假设每次轮询都刚好相隔 1 秒。

模型输入共 6 个数字：

| 特征 | 怎么理解 |
| --- | --- |
| packet_rate | 每秒经过多少包 |
| byte_rate | 每秒经过多少字节 |
| mean_packet_bytes | 最近窗口平均每包多大 |
| is_icmp | 是否为 ICMP |
| is_tcp | 是否为 TCP |
| is_udp | 是否为 UDP |

后三项是协议类型的独热表示。源 IP 不输入分类器，避免模型直接记住“h3 就是攻击者”。首次统计和计数器重置的窗口不计算速率。

只在 s1 的主机入口计数，避免同一个包经过 s1、s2 后被计算两次。

## 5. 阈值方法和随机森林

阈值方法判断包速率是否超过设定值，容易解释，但只看一个特征。随机森林由多棵决策树组成，综合包速率、字节速率、平均包长、协议判断异常概率。

模型不是先天知道什么是攻击。程序在关闭防御的条件下生成正常/异常流量，保存流量发生时间，再给完整落在对应时间范围内的样本标注标签。

不同轮次分别用于训练、验证和测试：训练集让模型学习，验证集选阈值，测试集最后评估一次。不能随机拆开同一轮中的相邻时间窗口来制造漂亮成绩。

## 6. 为什么不一报警就永久封禁

模型可能误判，因此本项目要求连续两个异常窗口才请求封禁。规则只持续 10 秒，随后交换机自动删除。攻击若仍持续，可以重新检测和封禁。

封禁时包到不了普通统计规则，计数可能降为零；这是防御造成的现象，不能解释为“攻击者已经停手”。

系统分三步记录：

1. `block_requested`：控制器发出了规则。
2. `rule_ack`：交换机通过 Barrier 回复确认处理完成，且没有收到对应规则错误。
3. `drop_observed`：后续轮询确实看到丢弃计数增长。

答辩时把这三类日志与吞吐量曲线一起展示，比只展示一条“Attack”文字更能说明闭环有效。

## 7. 建议的 5 分钟演示顺序

1. 介绍拓扑和 10 Mbit/s 瓶颈，指出正常客户端和场景主机。
2. 在看板选择 UDP 的无防御轮次，回放，观察正常 TCP 业务的接收吞吐量。
3. 切换到相同种子对应的 RF 轮次，回放封禁请求、规则确认和实际丢弃。
4. 检查攻击仍在持续期间正常业务是否恢复；不要把攻击停止后的自然恢复算成防御成功。
5. 展示阈值和 RF 的分类指标以及正常场景误封次数，说明结果的局限。

## 8. 常见答辩问题

**和普通交换机有什么区别？** 数据仍由交换机转发，但控制器可以通过程序动态修改处理规则。

**为什么不能只做离线分类？** 分类正确不等于网络恢复。还要证明规则安装成功、数据实际被丢弃、正常业务受到保护。

**为什么模型运行几毫秒，响应却要几秒？** 推理只是其中一步，还需要等待统计采样、连续窗口判定、控制消息传输和交换机执行。

**随机森林一定比阈值好么？** 不一定。对简单高包速率洪泛，阈值可能已经足够；是否更好应由真实测试和误报情况决定。

**是不是已经实现了通用网络安全系统？** 不是。它验证的是固定拓扑下对已知异常流量的检测和控制过程，尚不覆盖未知攻击、伪造源地址、复杂业务混合和生产网络规模。

**本项目体现哪些计网知识？** 以太网帧、MAC 学习、链路带宽、排队与丢包、TCP/UDP/ICMP、控制平面与数据平面、流表优先级、统计计数和网络性能测量。
